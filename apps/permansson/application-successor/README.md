# Permansson application successor - recovery implementation (new reconstruction)

**Status: reconstructed development candidate, NOT the original 29-page/39-page kits, not a certified release.** This new source was rebuilt after original prior-turn workspace artifacts became unavailable. It is intentionally limited to two numeric routes and has no general strategic-world importer or new Lean correspondence proof.

The package invokes the *unchanged* C10/C11 native producers on the supplied audited source checkout, rechecks saved receipt bytes through their native independent checkers, and reports numerical results separately from Lean replay, scientific identification and independent acceptance. It verifies exact SHA-256 bytes of the native scripts and their directly imported research modules against its own closed registry. This is a source-integrity check, not a trusted attestation of full transitive imports. It does not execute bundle-supplied code. **The caller must trust the source checkout and execution machine.** Windows is unqualified.

## Run without installation

```bash
python cli.py capabilities
python cli.py resources --output /tmp/permansson-resource-export-new
python cli.py run /tmp/permansson-resource-export-new/examples/c10.request.json \
  --source-root /path/to/PermanssonLean-main \
  --output /tmp/permansson-c10-new
```

Use the C11 periodic/multiclass examples similarly, with a distinct new output directory. `--source-root` is the extracted repository snapshot or a matching clean checkout at source cut `3492b26707788293ca88c66637b6ba021c7e478d`; the program checks native provider hashes, not a fake Git commit for a ZIP. `--output` must not already exist and must be outside the source root.

The corresponding `application_result.json` always has `lean_status=NOT_EXECUTED`, `scientific_claims_verified=false`, `empirical_identification=NOT_IDENTIFIED` and `independent_application_acceptance=NOT_ASSESSED`. It is not an automatic GR/PR determination or authority to execute any external action.
