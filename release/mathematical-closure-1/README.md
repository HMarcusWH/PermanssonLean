## Exact merged-M reproduction

The postmerge pre-seal gate accepts `--reproduction-zip` plus
`--reproduction-ids` only as a pair. The ZIP must be the **original**
GitHub Actions `pr113-clean-paper-rebuild-draft` archive from a real successful
`clean-paper-rebuild` job at merged **M** on `main`. The ID JSON has
`run_id`, `run_attempt`, `job_id`, `check_run_id`, and `artifact_id`.
`final_closure_reproduction_auth.py` independently rechecks GitHub metadata,
the authoritative artifact digest, and identical actual PDFs, manifests,
archives, logs and page PNGs from two source roots. Without this genuine
receipt the full pre-seal gate remains closed. Even a valid clean-build receipt
is **not** mathematical review, scholarly approval or release authorization.

## Two independent roots, one fresh TeX output pathname

The actual October 24 clean-paper logs showed identical eight-page PDFs and
all eight identical rendered PNGs. Only the LaTeX output log differed, from
pdfTeX wrapping different absolute output paths across terminal lines. The
latex_log_sha256 field, source manifest and ZIP checksums then diverged.

The two-root builder now creates two distinct no-hardlink exact-SHA Git source
clones, runs their TeX compilations sequentially through the same freshly
created absolute output staging pathname, then moves all generated bytes
unchanged to separate first/ and second/ directories. It requires the staging
location to be empty before both builds. Raw TeX logs, scientific diagnostics,
all PDF pages and the original SHA256SUMS comparison are preserved.

A standalone local pdfTeX smoke with two different source directories yielded
identical PDF bytes and captured full logs. That is not a verified Permansson
manuscript run. The actual clean-paper GitHub action must pass again on exact
final H and later on a genuinely authorized merged M. Neither a local smoke
nor the BUILD success indicates independent scholarly or mathematical review.
